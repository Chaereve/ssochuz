Đăng bài thẳng lên Cloudflare — không cần GitHub, không đợi build

Bấm Lưu là dữ liệu ghi vào Cloudflare KV qua Worker, người đọc thấy sau 1–2 giây. Trang web vẫn nằm trên Cloudflare Pages, chỉ có dữ liệu truyện là đi đường riêng (nhanh, gần như miễn phí).

  1. Vào dash.cloudflare.com → Workers & Pages → Create → Worker → đặt tên chuseoz-cms → Deploy.
  2. Bấm Edit code → xoá hết → dán nội dung file worker/cms.js trong repo → Deploy.
  3. Tab Settings → Variables and Secrets: thêm secret ADMIN_KEY = một chuỗi dài bạn tự đặt (>= 24 ký tự).
  4. Tab Bindings → Add → KV namespace: tạo namespace chuseoz, đặt tên biến là CZ_KV → Deploy lại.
  5. Copy URL Worker dán vào ô trên, rồi bấm Kiểm tra & kết nối. Sau đó bấm Nạp dữ liệu lên KV (một lần) để đưa 62 bộ hiện có lên.

Chi tiết đầy đủ (kèm cách dùng wrangler và cách mở số liệu Firebase): xem worker/README.md.

Đồng bộ & bảo trì

Đồng bộ đọc lại trang danh sách + lịch ra chương trên Blogger rồi ghép vào dữ liệu KV (không ghi đè chương bạn đã sửa).

Quy trình làm việc hằng ngày

  1. Viết chương mới (Blogger như cũ) → mở admin → Đăng chương nhanh → dán → Đăng. Hoặc bấm Đồng bộ từ Blogger để lấy số chương/tình trạng mới.
  2. Sửa thông tin bộ (bìa, tóm tắt, tình trạng, 18+, couple) → Thư viện → Sửa → Lưu.
  3. Đổi hàng loạt: tick nhiều bộ ở Thư viện → chọn thao tác.
  4. Sao lưu định kỳ bằng nút “Sao lưu toàn bộ” (1 file JSON, phục hồi được bất cứ lúc nào).

Phím tắt

Ctrl/⌘ + S lưu · Ctrl/⌘ + K tìm kiếm · Esc đóng thông báo · 1…7 chuyển mục khi con trỏ không ở ô nhập.

Vì sao không dùng GitHub nữa?

Mỗi lần lưu qua GitHub là một commit → Cloudflare phải build lại toàn site (tốn vài phút và tốn phút CI). Với Worker + KV, dữ liệu đi thẳng tới nơi phục vụ, không dựng lại gì cả, nên nhanh và rẻ. Code (HTML/CSS/JS) vẫn nằm trên GitHub như cũ — chỉ khi sửa code mới cần deploy.

Số liệu đọc

Site mới đọc số liệu thật từ Firebase cũ. Để mở: Firebase Console → Firestore → Rules → cho phép read với novelData (mẫu trong worker/README.md §5).
